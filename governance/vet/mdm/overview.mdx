---
title: "Deploy vet with MDM"
description: "Install, update, and remove vet across endpoint fleets, then add optional visibility tasks through your MDM."
---

Use your mobile device management (MDM) platform to deploy `vet` across macOS, Linux, and Windows endpoints. This guide works with any MDM that can deploy files or run shell or PowerShell commands, such as Jamf, Intune, JumpCloud, Mosyle, or Kandji.

The core deployment does not depend on a SafeDep-provided MDM script. Use your MDM to manage the CLI lifecycle. Add SafeDep fleet scripts as separate, optional tasks after `vet` is installed.

The deployment has two parts:

1. Install and manage the `vet` CLI on each endpoint.
2. Add optional MDM tasks that run `vet` to collect and sync inventory.

<Note>
  Installing `vet` does not require a SafeDep account. SafeDep Cloud credentials are required only when a task sends data to Endpoint Hub.
</Note>

## Before you start

You need:

- An MDM policy that can run a shell or PowerShell command, or deploy a package.
- Administrator access on the target endpoints.
- A small test device group for the first deployment.
- A selected install method: Homebrew, npm, or a pre-built binary.

Use the same install method for installation, updates, and removal. Do not mix package managers on the same endpoint.

## Install vet

Choose the method that matches the software already available on your endpoints.

<Tabs>
  <Tab title="Homebrew (macOS and Linux)">
    Run the command in the user context that owns the Homebrew installation. Do not run Homebrew as root.

    ```sh
    brew install safedep/tap/vet
    ```
  </Tab>
  <Tab title="npm">
    Use this method when Node.js and npm are already managed on the endpoint.

    ```sh
    npm install -g @safedep/vet
    ```
  </Tab>
  <Tab title="Pre-built binary">
    Download the archive for each operating system and architecture from [vet releases](https://github.com/safedep/vet/releases). Verify it with the published `checksums.txt` file, then add the extracted `vet` binary to your MDM package.

    Install the binary in a system path:

    <Tabs>
      <Tab title="macOS">
        ```sh
        install -d -o root -g wheel -m 0755 /usr/local/bin
        install -o root -g wheel -m 0755 vet /usr/local/bin/vet
        ```
      </Tab>
      <Tab title="Linux">
        ```sh
        install -d -o root -g root -m 0755 /usr/local/bin
        install -o root -g root -m 0755 vet /usr/local/bin/vet
        ```
      </Tab>
      <Tab title="Windows">
        Run this PowerShell command as an administrator. It installs `vet.exe` under `Program Files` and adds that directory to the system `PATH`.

        ```powershell
        $installDir = Join-Path $env:ProgramFiles "SafeDep\vet"
        New-Item -ItemType Directory -Force -Path $installDir | Out-Null
        Copy-Item .\vet.exe (Join-Path $installDir "vet.exe") -Force

        $machinePath = [Environment]::GetEnvironmentVariable("Path", "Machine")
        if (($machinePath -split ";") -notcontains $installDir) {
          [Environment]::SetEnvironmentVariable(
            "Path",
            "$machinePath;$installDir",
            "Machine"
          )
        }
        ```
      </Tab>
    </Tabs>
  </Tab>
</Tabs>

Assign the install policy to your test group first. After the policy runs, verify the installation:

<Tabs>
  <Tab title="macOS and Linux">
    ```sh
    command -v vet
    vet version
    ```
  </Tab>
  <Tab title="Windows">
    ```powershell
    Get-Command vet
    vet version
    ```
  </Tab>
</Tabs>

The first command must return the managed `vet` path. The second command must return the installed version. Start a new command session before you verify a Windows installation so it reads the updated system `PATH`.

## Update vet

Update `vet` through the same MDM policy and install method:

<Tabs>
  <Tab title="Homebrew (macOS and Linux)">
    ```sh
    brew upgrade safedep/tap/vet
    ```
  </Tab>
  <Tab title="npm">
    ```sh
    npm install -g @safedep/vet@latest
    ```
  </Tab>
  <Tab title="Pre-built binary">
    Download and verify the required release, then replace the managed `vet` binary in your MDM package. Re-run the install policy to replace `/usr/local/bin/vet` on macOS and Linux or `vet.exe` under `Program Files` on Windows.
  </Tab>
</Tabs>

Run `vet version` after the update and confirm that it reports the expected version.

## Uninstall vet

Disable any MDM tasks that run `vet` before you remove the CLI. Then use the uninstall command that matches the install method.

<Tabs>
  <Tab title="Homebrew (macOS and Linux)">
    ```sh
    brew uninstall safedep/tap/vet
    ```
  </Tab>
  <Tab title="npm">
    ```sh
    npm uninstall -g @safedep/vet
    ```
  </Tab>
  <Tab title="Pre-built binary">
    <Tabs>
      <Tab title="macOS and Linux">
        ```sh
        rm -f /usr/local/bin/vet
        ```
      </Tab>
      <Tab title="Windows">
        Run this PowerShell command as an administrator:

        ```powershell
        $installDir = Join-Path $env:ProgramFiles "SafeDep\vet"
        Remove-Item $installDir -Recurse -Force -ErrorAction SilentlyContinue

        $machinePath = [Environment]::GetEnvironmentVariable("Path", "Machine")
        $updatedPath = (($machinePath -split ";") |
          Where-Object { $_ -and $_ -ne $installDir }) -join ";"
        [Environment]::SetEnvironmentVariable("Path", $updatedPath, "Machine")
        ```
      </Tab>
    </Tabs>
  </Tab>
</Tabs>

Run `command -v vet` on macOS or Linux, or `Get-Command vet` on Windows, after removal. It must not return a path.

## Add fleet visibility tasks

Installing `vet` makes the CLI available, but it does not schedule scans. Deploy each visibility task as a separate MDM policy. This lets you change its command, credentials, and schedule without reinstalling `vet`.

The current fleet task is [`vet_endpoint_scan.sh`](https://github.com/safedep/vet/blob/main/scripts/mdm/vet_endpoint_scan.sh). It supports macOS and Linux. It runs `vet endpoint scan` for local users and collects AI tools, coding agents, MCP servers, and agent skills. It does not support Windows.

<Steps>
  <Step title="Deploy the script">
    Download the script from the vet repository and deploy it to a managed path on each endpoint. Make the file executable.

    ```sh
    chmod 0755 /path/to/vet_endpoint_scan.sh
    ```
  </Step>
  <Step title="Add SafeDep Cloud credentials">
    Create an API key and get your Tenant ID from [SafeDep Cloud settings](https://app.safedep.io/settings/api-keys). Store both values in your MDM secret store, then pass them as environment variables:

    ```sh
    SAFEDEP_API_KEY="<api-key>" \
    SAFEDEP_TENANT_ID="<tenant-id>" \
    /path/to/vet_endpoint_scan.sh
    ```

    Cloud sync starts only when both variables are set. Without them, the script scans locally and the inventory does not appear in Endpoint Hub.
  </Step>
  <Step title="Choose the execution context">
    Run the script as root to scan every local human account. The script runs each scan in that user's account context so SafeDep Cloud can attribute inventory correctly on shared machines.

    Run it as the logged-in user to scan only that user. This mode uses the user's full `PATH` and gives the most complete CLI tool discovery on macOS.
  </Step>
  <Step title="Assign a schedule">
    Assign the policy to a test group and choose a schedule that matches how often you need the inventory refreshed. The script continues to the next user if one user scan fails and reports the final result in the MDM job output.
  </Step>
  <Step title="Verify the inventory">
    Open [SafeDep Cloud](https://app.safedep.io), select **Endpoint Hub**, open the endpoint, and select the **Inventory** tab. Confirm that the endpoint and its discovered items appear.
  </Step>
</Steps>

To remove this task, disable its MDM policy and remove the managed script. This does not uninstall `vet`.
