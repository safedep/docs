---
title: Generate an AI BOM with vet
description: "Produce a CycloneDX AI Bill of Materials from your source code with vet, listing the AI and LLM SDKs your application actually calls."
---

An AI Bill of Materials (AI BOM) inventories the AI and LLM services your application actually uses, based on the calls in your source code rather than the packages you declared. `vet` builds one by scanning source code, matching function calls against embedded AI SDK signatures, and writing the result into a [CycloneDX](/concepts/sbom) BOM.

This guide covers producing the AI BOM and reading its output. To extend detection to an SDK `vet` does not yet recognize, see [Write custom AI SDK signatures](/governance/vet/ai-sdk-signatures).

<Warning>
Code analysis in `vet` is experimental and may introduce breaking changes.
</Warning>

## Prerequisites

- `vet` [installed](/governance/vet/quickstart)
- Access to the source code you want to analyze

## Generate the AI BOM

<Steps>
  <Step title="Analyze source code">
    Parse your source and store call-graph matches in a SQLite database. Use `--app` for your application directories and `--import-dir` for vendored or third-party dependencies.

    ```bash
    vet code scan --db code.db \
      --app ./src \
      --import-dir ./vendor
    ```

    Restrict languages with `--lang` (for example `--lang python`); omit it to scan every supported language. Skip test or generated code with `--exclude`, which takes a regular expression:

    ```bash
    vet code scan --db code.db \
      --app ./src \
      --exclude ".*test.*" --exclude ".*__pycache__.*"
    ```
  </Step>

  <Step title="Produce the CycloneDX AI BOM">
    Run `vet scan` with the code database and write a CycloneDX report. The code analysis enriches the SBOM with AI component evidence.

    ```bash
    vet scan -D ./src --code code.db --report-cdx ai-bom.json
    ```

    `ai-bom.json` is a standard CycloneDX document. AI components carry an `ai` property so downstream tooling can filter them.
  </Step>

  <Step title="Inspect matches before or without a BOM">
    To review what was detected directly from the database, query the matches tagged `ai`:

    ```bash
    vet code query --db code.db --tag ai
    ```

    Narrow the results by language, vendor, or file path:

    ```bash
    vet code query --db code.db --tag ai --language python --limit 200
    vet code query --db code.db --vendor OpenAI
    vet code query --db code.db --file src/agents/
    ```
  </Step>
</Steps>

## Read the AI BOM

Where an AI SDK call shows up in the BOM depends on which directory it was found in.

### Application-level components

AI calls in your own code (the `--app` directories) become standalone components with an `xbom:` bom-ref. The name is built from the signature's product and service, the publisher is the vendor, and the `ai` property marks it as an AI component:

```json
{
  "bom-ref": "xbom:anthropic.client",
  "type": "library",
  "name": "Anthropic API - AI client",
  "publisher": "Anthropic",
  "evidence": {
    "occurrences": [
      { "location": "src/app.py", "line": 15, "additionalContext": "anthropic.Anthropic" }
    ]
  },
  "properties": [
    { "name": "ai", "value": "true" }
  ]
}
```

This is the primary output when you scan first-party code. Detection is call-graph based, so an SDK that is imported but never called does not produce a component.

### Package-level components

When AI signatures match inside dependency source scanned through `--import-dir`, the evidence attaches to the corresponding declared package instead of a standalone component. That package gains `source-code-analysis` identity evidence, the call locations, and the `ai` property:

```json
{
  "bom-ref": "pkg:pypi/openai@1.51.0",
  "evidence": {
    "identity": [
      { "methods": [{ "technique": "source-code-analysis", "confidence": 1.0 }] }
    ],
    "occurrences": [
      { "location": "vendor/openai/resources/responses.py", "line": 42, "additionalContext": "openai.OpenAI" }
    ]
  },
  "properties": [
    { "name": "ai", "value": "true" }
  ]
}
```

Packages that are used in code but scanned without `--import-dir` still appear in the BOM and are tagged `used-in-code` in the scan summary; the AI evidence for them shows up as the application-level components above.

### Filter AI components from the BOM

The `ai` property lets you extract AI components programmatically. For example, with `jq`:

```bash
jq '.components[] | select(.properties[]? | .name == "ai" and .value == "true") | .name' ai-bom.json
```

## Run it in CI

Generate the AI BOM on each build and keep it as an artifact:

```yaml
- name: Build code analysis database
  run: vet code scan --app ./src --db code.db

- name: Generate AI BOM
  run: vet scan -D . --code code.db --report-cdx ai-bom.json
```
