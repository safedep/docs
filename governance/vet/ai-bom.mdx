---
title: Generate an AI BOM with vet
description: "Produce a CycloneDX AI Bill of Materials from source code with vet, with file and line evidence for every detected AI SDK call."
---

A dependency manifest lists the AI packages your project declares. It does not show whether the code calls them, or where. `vet` reads the source, finds the AI and LLM SDK calls in it, and writes them into a [CycloneDX](/concepts/sbom) AI Bill of Materials (AI BOM), with the file and line for every call site it detected.

Detection covers OpenAI, Anthropic, Google Gemini, xAI Grok, Mistral, AWS Bedrock, Hugging Face, LangChain, LangGraph, CrewAI, LlamaIndex, Vercel AI SDK, Spring AI, and the Model Context Protocol SDKs, among others, across five languages: Go, Python, JavaScript, TypeScript, and Java. Browse the full signature set in the [vet repository](https://github.com/safedep/vet/tree/main/signatures). If your codebase uses an SDK that `vet` does not recognize, [write a custom signature](/governance/vet/ai-sdk-signatures).

<Warning>
Code analysis in `vet` is experimental and may introduce breaking changes.
</Warning>

## Prerequisites

- `vet` [installed](/governance/vet/quickstart)
- Access to the source code you want to analyze

## Generate the AI BOM

<Steps>
  <Step title="Scan the source code">
    The first pass parses your source files and records every AI SDK call in a local SQLite database. Point `--app` at your own code. If you keep vendored or third-party source in the repo, point `--import-dir` at it so `vet` can attribute those calls to the right package.

    ```bash
    vet code scan --db code.db \
      --app ./src \
      --import-dir ./vendor
    ```

    Skip test and generated code with `--exclude` (a regular expression), and restrict languages with `--lang` when you want a faster scan:

    ```bash
    vet code scan --db code.db \
      --app ./src \
      --lang python \
      --exclude ".*test.*" --exclude ".*__pycache__.*"
    ```
  </Step>

  <Step title="Write the CycloneDX AI BOM">
    The second pass runs a normal `vet` scan, enriches it with the recorded code analysis, and writes the BOM:

    ```bash
    vet scan -D ./src --code code.db --report-cdx ai-bom.json
    ```

    `ai-bom.json` is a standard CycloneDX document. Every AI component in it carries an `ai` property, so downstream tooling can filter on it.
  </Step>

  <Step title="Inspect detections directly (optional)">
    You can review what `vet` found without generating a BOM. Query the database for matches tagged `ai`:

    ```bash
    vet code query --db code.db --tag ai
    ```

    Narrow the results by language, vendor, or file path:

    ```bash
    vet code query --db code.db --tag ai --language python --limit 200
    vet code query --db code.db --vendor OpenAI
    vet code query --db code.db --file src/agents/
    ```
  </Step>
</Steps>

## Read the AI BOM

A detection lands in one of two places in the BOM, depending on where `vet` found the call.

### Calls in your own code

AI SDK calls in `--app` directories become standalone components with an `xbom:` bom-ref. The signature's vendor becomes the publisher, and the `ai` property marks the component:

```json
{
  "bom-ref": "xbom:anthropic.client",
  "type": "library",
  "name": "Anthropic API - AI client",
  "publisher": "Anthropic",
  "evidence": {
    "occurrences": [
      { "location": "src/app.py", "line": 15, "additionalContext": "anthropic.Anthropic" }
    ]
  },
  "properties": [
    { "name": "ai", "value": "true" }
  ]
}
```

This is the output you will read most often. Detection follows calls, so an SDK that is imported but never called produces no component.

### Calls inside dependencies

When a signature matches inside dependency source scanned through `--import-dir`, the evidence attaches to the declared package instead. The package gains `source-code-analysis` identity evidence, the call locations, and the `ai` property:

```json
{
  "bom-ref": "pkg:pypi/openai@1.51.0",
  "evidence": {
    "identity": [
      { "methods": [{ "technique": "source-code-analysis", "confidence": 1.0 }] }
    ],
    "occurrences": [
      { "location": "vendor/openai/resources/responses.py", "line": 42, "additionalContext": "openai.OpenAI" }
    ]
  },
  "properties": [
    { "name": "ai", "value": "true" }
  ]
}
```

### Filter AI components

The `ai` property makes extraction a one-liner. With `jq`:

```bash
jq '.components[] | select(.properties[]? | .name == "ai" and .value == "true") | .name' ai-bom.json
```

<Note>
Two behaviors to keep in mind when you read results. Providers that applications reach through the OpenAI-compatible mode of the `openai` SDK (DeepSeek and Moonshot document this as their official path) appear as OpenAI usage, because the code calls the `openai` SDK. TypeScript needs no separate handling: JavaScript signatures cover it.
</Note>

## Run it in CI

Generate the AI BOM on each build and keep it as an artifact:

```yaml
- name: Build code analysis database
  run: vet code scan --app ./src --db code.db

- name: Generate AI BOM
  run: vet scan -D ./src --code code.db --report-cdx ai-bom.json
```
