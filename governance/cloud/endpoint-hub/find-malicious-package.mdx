When SafeDep flags a package as malicious, find the endpoints that tried to install it, the endpoints that installed it, and the projects that depend on it.

<Note>
  This guide needs the SafeDep Cloud Team or Enterprise plan. See [SafeDep Plans](/governance/cloud/plans).
</Note>

## Prerequisites

- PMG syncs to your tenant from developer machines and CI runners. See [Package Guard](/governance/cloud/endpoint-hub/package-guard).
- Vet scans sync to your tenant. See [Cloud Sync](/governance/cloud/sync).
- To run the queries from a terminal, sign in to the `safedep` CLI. See the [SafeDep Cloud Quickstart](/governance/cloud/quickstart).

## See recent blocks

<Steps>
  <Step title="Open the endpoint list">
    Sign in to [app.safedep.io](https://app.safedep.io) and select **Endpoints**.
  </Step>
  <Step title="Show only endpoints with a block">
    Turn on **Has Blocked Events**. The **Live Activity** panel shows recent events, blocks included, and the endpoint of each event.
  </Step>
  <Step title="Open an endpoint">
    Select the endpoint, then select **Package Events**. Each blocked package has a **Report** link to the analysis of the package.
  </Step>
</Steps>

## Find every endpoint that tried to install the package

Select **Query** in the sidebar and run this query. Replace `ECOSYSTEM_PYPI` and `reqeusts` with the ecosystem and the name of the package. The query also finds the installs that a user confirmed after PMG flagged the package.

```sql
SELECT endpoints.identifier,
       package_guard_events.package_action,
       package_guard_events.package_version,
       package_guard_events.timestamp
FROM package_guard_events
JOIN endpoints ON endpoints.id = package_guard_events.invocation_id
WHERE package_guard_events.package_action IN (
    'PMG_PACKAGE_ACTION_BLOCKED', 'PMG_PACKAGE_ACTION_CONFIRMED')
  AND package_guard_events.package_ecosystem = 'ECOSYSTEM_PYPI'
  AND package_guard_events.package_name = 'reqeusts'
ORDER BY package_guard_events.timestamp DESC
```

To run the same query from a terminal, save it as `blocked.sql` and run `safedep query exec --sql-file blocked.sql`.

<img src="/images/cloud/sql-blocked-packages.png" alt="SafeDep Cloud query console with the endpoints that tried to install one package" />

In the `package_action` column, `1` is a block and `2` is an install that a user confirmed.

PMG records an event when it blocks, holds back, or trusts a package, and when a user confirms the install of a flagged package. It does not record an event for each package that it allows. An install that happened before SafeDep flagged the package does not show here. To find those, check your projects.

## Find every project that depends on the package

Filter on the ecosystem, the name, and each malicious version. A name alone also matches safe versions, and packages with the same name in other ecosystems.

```sql
SELECT projects.name, packages.name, packages.version
FROM packages
JOIN boms ON boms.id = packages.bom_id
JOIN project_versions ON project_versions.id = boms.project_version_id
JOIN projects ON projects.id = project_versions.project_id
WHERE packages.ecosystem = 'ECOSYSTEM_PYPI'
  AND packages.name = 'reqeusts'
  AND packages.version IN ('2.32.6')
```

The query returns each project whose latest Vet scan has the package in its dependency tree. For the schema and more examples, see the [SQL query guide](/reference/sql-query).
