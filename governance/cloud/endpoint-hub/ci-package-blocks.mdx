title: "Review Package Blocks Across CI Pipelines"
description: "See every package that PMG blocked or held back on your CI runners, across all repositories, in SafeDep Cloud."
---

PMG in CI blocks a malicious package and fails the job. One failed job shows one block. SafeDep Cloud shows the blocks from every pipeline in one place.

<Note>
  This guide needs the SafeDep Cloud Team or Enterprise plan. See [pricing](https://safedep.io/pricing).
</Note>

## Prerequisites

- PMG runs in your pipelines and syncs to your tenant:
  - In GitHub Actions, set the `api-key` and `tenant-id` inputs of the PMG action. See [PMG in GitHub Actions](/package-security/pmg/github-actions).
  - In other CI systems, run `pmg cloud sync` at the end of the job. See [Package Guard](/governance/cloud/endpoint-hub/package-guard#manual-sync).

## Review one pipeline

<Steps>
  <Step title="Open the endpoint list">
    Sign in to [app.safedep.io](https://app.safedep.io) and select **Endpoints**. In GitHub Actions, each repository is one endpoint by default. Set the `endpoint-id` input of the PMG action to change it.
  </Step>
  <Step title="Open the endpoint">
    Select the endpoint, then select **Package Events**. Each session shows the install command and its outcome, such as **Blocked** or **Success**. Each package row shows its action, such as **Blocked** or **Cooldown**.
  </Step>
  <Step title="Filter the events">
    Use **Package action** or **Session outcome** to show only the blocks.
  </Step>
</Steps>

## Review all pipelines

PMG records the CI provider with each event. This query lists the malicious package blocks and the cooldown holds on all CI runners:

```sql
SELECT endpoints.identifier,
       package_guard_events.ci_provider,
       package_guard_events.package_name,
       package_guard_events.package_action,
       package_guard_events.timestamp
FROM package_guard_events
JOIN endpoints ON endpoints.id = package_guard_events.invocation_id
WHERE package_guard_events.ci_provider IS NOT NULL
  AND package_guard_events.package_action IN (
    'PMG_PACKAGE_ACTION_BLOCKED', 'PMG_PACKAGE_ACTION_COOLDOWN_BLOCKED')
ORDER BY package_guard_events.timestamp DESC
```

Run it from **Query** in the sidebar, or with `safedep query exec --sql-file`.

<img src="/images/cloud/sql-ci-blocks.png" alt="SafeDep Cloud query console with the package blocks on all CI runners" />

The console shows enum columns as numbers. In `package_action`, `1` is a malicious package block and `4` is a cooldown hold. In `ci_provider`, `1` is GitHub Actions, `2` is GitLab CI, and `3` is Jenkins.
