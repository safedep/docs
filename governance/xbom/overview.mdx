---
title: "xBom"
description: "xBom generates a Bill of Materials of the AI, cloud and crypto components that it finds in your source code."
---

Traditional BOM tools read only manifest files such as `requirements.txt` or `pom.xml`. [xBom](https://github.com/safedep/xbom) analyzes your source code to find the AI SDKs, cloud APIs and cryptography that your application calls, and writes them as a BOM. See [What is an SBOM?](/concepts/sbom).

xBom finds evidence of AI SDKs, cloud APIs and cryptography in Python and Java code, with partial JavaScript support, as of v0.0.3. It writes a standard CycloneDX BOM. Community signatures detect each component. The signatures are built into xBom, so to add one, contribute it to the xBom repository.

<Note>
  For an SBOM or an AI BOM, use vet. See [Generate an SBOM](/governance/cyclonedx-sbom) and [Detect Shadow AI in Code](/governance/shadow-ai-detection). Vet uses the same code analysis with more signatures, and writes the AI BOM and the dependency SBOM in one CycloneDX file. Use xBom when you want only the components that code analysis finds, without a dependency scan.
</Note>
