`vet` supports [CycloneDX v1.6](https://cyclonedx.org/docs/1.6/json) SBOM generation. The generated SBOM lists all packages and their dependencies, including security metadata: detected vulnerabilities, malware, and license information.

Vet writes CycloneDX, not SPDX. To scan an SBOM that another tool wrote, including SPDX, see [Scan an SBOM](/governance/vet/dependency-inventory).

## Generate the SBOM

Generate an SBOM with a custom application name:

```bash
vet scan -D /path/to/project \
  --report-cdx report.cdx.json \
  --report-cdx-app-name myproject
```

`--report-cdx-app-name` is optional. With `-D`, the default name is the last element of the `-D` path, so `-D .` gives the name `.`. With `--lockfiles`, the default name is `vet-scanned-project`.

## What the SBOM includes

- **Package inventory:** all direct and transitive dependencies, and the dependency graph
- **Vulnerabilities:** known vulnerabilities from OSV and other sources, with CVSS ratings
- **Licenses:** the license identifiers of each component
- **Malware:** the results of malicious package analysis, as `vulnerabilities` entries

To also add the AI SDKs and services that your code calls, see [Generate the AI BOM](/governance/shadow-ai-detection#generate-the-ai-bom).

## Write other reports in the same scan

Generate multiple report formats simultaneously:

```bash
vet scan -D /path/to/project \
  --report-cdx sbom.cdx.json \
  --report-json results.json \
  --report-markdown report.md \
  --report-cdx-app-name "production-app"
```

## Generate the SBOM in CI/CD

<Tabs>
  <Tab title="GitHub Actions">
    ```yaml
    name: Generate SBOM
    on: [push, pull_request]
    
    jobs:
      sbom:
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4
          
          - name: Generate SBOM
            run: |
              docker run --rm -v "$PWD:/app" ghcr.io/safedep/vet:latest \
                scan -D /app \
                --report-cdx /app/sbom.cdx.json \
                --report-cdx-app-name "${{ github.repository }}"

          - name: Upload SBOM
            uses: actions/upload-artifact@v4
            with:
              name: sbom
              path: sbom.cdx.json
    ```
  </Tab>
  
  <Tab title="GitLab CI">
    The vet image starts `vet` as its entrypoint. Set an empty entrypoint so that GitLab can run the script.

    ```yaml
    generate-sbom:
      image:
        name: ghcr.io/safedep/vet:latest
        entrypoint: [""]
      script:
        - vet scan -D . --report-cdx sbom.cdx.json --report-cdx-app-name "$CI_PROJECT_NAME"
      artifacts:
        reports:
          cyclonedx: sbom.cdx.json
        paths:
          - sbom.cdx.json
        expire_in: 30 days
    ```

    The `cyclonedx` report needs GitLab Ultimate. On other tiers, keep only `paths`.
  </Tab>
</Tabs>

## Validate and Convert the SBOM

Use the [CycloneDX CLI](https://github.com/CycloneDX/cyclonedx-cli) to validate the SBOM or convert it to XML. Install it with `brew install cyclonedx/cyclonedx/cyclonedx-cli`, or run its container image:

```bash
# Validate against CycloneDX 1.6. The CLI defaults to 1.7.
docker run --rm -v "$PWD:/data" cyclonedx/cyclonedx-cli \
  validate --input-file /data/sbom.cdx.json --input-version v1_6 --fail-on-errors

# Convert to XML
docker run --rm -v "$PWD:/data" cyclonedx/cyclonedx-cli \
  convert --input-file /data/sbom.cdx.json --output-file /data/sbom.xml \
  --output-format xml --output-version v1_6
```

Tools such as Dependency-Track can import the SBOM to monitor it for new vulnerabilities.
