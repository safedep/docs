---
title: "Sandbox Your AI Coding Agent"
description: "Run Claude Code, Codex, or Pi in the PMG sandbox to block credential reads and limit the hosts the agent can reach."
---

A coding agent runs many commands in a session, and each command can read your credentials or send data out. `pmg sandbox exec` runs the agent and every process it starts under one sandbox policy.

The sandbox:

- Blocks reads and writes of credential files in the repository and in your home directory.
- Removes secret variables, model API keys included, from the agent environment.
- Makes the agent hook configuration read-only, so the agent cannot remove a hook such as [Gryph](/ai-security/gryph-overview).
- Lets the agent write only in the repository, temporary directories, and tool caches.
- Sends every outbound connection through a PMG proxy that applies a network policy.

<Note>
  `pmg sandbox exec` is experimental. It runs on macOS and on Linux with the Landlock driver. It does not run with Bubblewrap or on Windows. The network policy steps need PMG v0.33.0 or later. Install PMG with the [PMG quickstart](/package-security/pmg/quickstart).
</Note>

## Run the agent in the sandbox

Each agent has a preset that adds its state directory, its own API key, and its own hosts.

<Tabs>
  <Tab title="Claude Code">
    ```bash
    pmg sandbox exec --sandbox-allow preset=claude -- claude
    ```
  </Tab>
  <Tab title="Codex">
    ```bash
    pmg sandbox exec --sandbox-allow preset=codex -- codex
    ```
  </Tab>
  <Tab title="Pi">
    ```bash
    pmg sandbox exec --sandbox-allow preset=pi -- pi
    ```
  </Tab>
</Tabs>

To apply the preset on every run in this repository, save it once:

```bash
pmg sandbox allow preset=claude
pmg sandbox exec -- claude
```

## Limit the hosts the agent can reach

By default the agent can reach every host, and PMG records each destination. Build a network policy from a session, then enforce it.

<Steps>
  <Step title="Run a normal session">
    ```bash
    pmg sandbox exec --sandbox-allow preset=claude -- claude
    ```

    Do the work that the agent usually does in this repository.
  </Step>
  <Step title="Propose a profile">
    ```bash
    pmg sandbox profile propose --last --new agent.yml
    ```

    The `agent.yml` profile allows each host that the session reached and denies every other destination. Remove each host that the agent does not need.
  </Step>
  <Step title="Run the agent under the profile">
    ```bash
    pmg sandbox exec --sandbox-profile agent.yml --network-mode enforce \
      --sandbox-allow preset=claude -- claude
    ```

    The preset keeps the agent hosts open, such as its model API and sign-in. The profile keeps the hosts that the repository needs.
  </Step>
</Steps>

When the proxy refuses a destination, PMG prints the destination and the rule after the agent exits:

```text
⊘ Network policy denied pastebin.com:443  rule *:*
  Allow it with pmg sandbox allow net-connect=pastebin.com:443.
```

## Fix a denied operation

The agent sees a permission error. After the session, find the cause and the command that allows it:

```bash
pmg sandbox explain --last
```

Git over SSH fails, because the sandbox blocks the SSH agent socket. Use an HTTPS remote.
