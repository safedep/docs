AI coding agents can read any file, write anywhere and run commands on your machine. **Gryph** hooks into your agents and records each action to a local audit log. You can query the log and review each session step by step. With a policy turned on, Gryph can also block a risky action before it runs. Gryph is not a sandbox: it does not isolate the agent process.

<Note>
Gryph runs fully locally. All data stays on your machine. There is no cloud component, no telemetry, and no SafeDep account or API key.
</Note>

## What Gryph does

- **Records agent activity.** Every file read, file write, and command execution becomes a structured event.
- **Stores it locally.** Events go to a local SQLite database on your machine. Nothing leaves your machine unless you export the events.
- **Lets you investigate.** Query and filter events, and show each session step by step with its file diffs.
- **Flags sensitive access.** Gryph detects when agents touch sensitive files like `.env`, keys, and secrets, and it can redact or hash captured content.
- **Blocks risky actions.** A YAML policy can block, warn about, guide or allow each action. The policy is off by default.
- **Exports and reports.** `gryph export` writes events as JSON Lines for a SIEM. By default it exports the last hour. Use `--since` for a longer period. `gryph stats` shows a dashboard, and `gryph cost` shows the token use and estimated cost of each session.

## Supported agents

Gryph supports Claude Code, Codex, Cursor, Devin CLI, Gemini CLI, OpenCode, Pi Agent and Windsurf. For the current list, the events captured for each agent and the setup that some agents need, see [Supported Agents](https://github.com/safedep/gryph#supported-agents) in the Gryph repository.

## Get started

<Steps>
  <Step title="Install Gryph">
    ```bash
    brew install safedep/tap/gryph
    ```
    Other methods (install script, npm, Go) are in the [Gryph README](https://github.com/safedep/gryph#quick-start).
  </Step>
  <Step title="Install hooks into your agents">
    ```bash
    gryph install
    ```
    Gryph detects the AI coding agents on your machine and wires up its hooks. To check the setup, run `gryph status`. To find a problem, run `gryph doctor`.
  </Step>
  <Step title="Use your agent normally">
    Run your AI coding agent as usual. Gryph records activity in the background.
  </Step>
  <Step title="Review what happened">
    ```bash
    gryph logs
    ```
    View recent agent activity. To see events as they happen, add `--follow`. Use `gryph query` to filter the audit log and `gryph sessions` to list recorded sessions. To show one session with its file diffs, run `gryph session <session-id> --show-diff`.

    To record file diffs, set the logging level to `full`. The default level is `standard`.

    ```bash
    gryph config set logging.level full
    ```
  </Step>
</Steps>

To remove the hooks from all agents, run `gryph uninstall`. To also delete the recorded data, add `--purge`.

## Block risky actions

Each rule of a Gryph policy has an action, such as `block`, `warn`, `guidance` or `allow`. A rule can match the action type, the file path, the command, the tool, the agent or the project. A blocked action never reaches the tool of the agent.

```bash
gryph policy init
gryph policy edit
gryph config set policy.enabled true
```

To see the result of the policy for one action, run `gryph policy test`. For the rule syntax and the limits of self-protection, see [Security Policy](https://github.com/safedep/gryph/blob/main/docs/security-policy.md) in the Gryph repository.

## How it differs from the SafeDep MCP server

- **Gryph** watches the agent. It records what the agent reads, writes and runs, and can block an action.
- **The [SafeDep MCP server](/ai-security/mcp-server)** gives the agent a tool. The agent asks SafeDep if a package is safe before it suggests an install.

Use them together. MCP helps the agent make safer suggestions, and Gryph keeps an audit trail of its actions.
