[Common Expression Language (CEL)](https://cel.dev/) is a safe, sandboxed expression language. Vet uses it to filter scan results, to query saved scan data, and to write policy rules. A CEL expression evaluates to true or false for each package, so you describe exactly which dependencies you care about.

## Why it matters

In Vet, one language covers ad-hoc filtering during a scan, repeatable queries over saved scan data, and policy as code. You learn the syntax once and use it for each job.

## CEL in other SafeDep tools

This page covers CEL in Vet. [Gryph](/ai-security/gryph-overview) policy rules can also use CEL conditions. The cloud [policy](/concepts/policy) of a SafeDep Cloud tenant does not use CEL. It uses typed settings and [label selectors](/concepts/labels). SafeDep Cloud queries use SQL.

## The input of an expression

A CEL expression in Vet receives data about each package, such as its coordinates, vulnerabilities, OpenSSF Scorecard data, source projects and licenses. See [Filtering](/reference/filtering) for each variable and example expressions.

Vet also has a newer policy engine, with a different input. Its rules use variables such as `pkg`, `project` and `manifest`. See the [v2 policy sample](https://github.com/safedep/vet/blob/main/samples/policy-v2.yml) in the Vet repository.
