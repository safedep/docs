An endpoint is a managed asset, such as a developer machine, a CI runner, or an agent sandbox, that runs SafeDep's open-source tools and reports what it finds to [Endpoint Hub](/governance/cloud/endpoint-hub/overview) in SafeDep Cloud.

<Note>
An endpoint here is a machine, not an API endpoint. For SafeDep's service hostnames, see [API Endpoints](/reference/endpoints).
</Note>

## Why it matters

Endpoints give a team visibility into what runs across its development infrastructure, such as AI coding agents, MCP servers, CLI tools, IDE extensions, and the packages developers install. That inventory is what you govern.

## What an endpoint reports

- The AI tooling, Agent Skills, IDE extensions and Neovim plugins that `vet endpoint scan` finds. AI tooling covers coding agents, MCP servers and CLI tools.
- Package install activity captured by [PMG](/package-security/pmg/overview) through Package Guard.
- The packages that AI coding agents check through the SafeDep MCP server. They appear per endpoint in [MCP Advisor](/governance/cloud/endpoint-hub/mcp-advisor), only if you set up the agent with the safedep CLI.

Each endpoint appears by hostname in Endpoint Hub, where you browse its inventory and package events. Reporting requires SafeDep Cloud credentials. Without them, scans run locally only.

An endpoint is also a subject of the cloud policy. With the cloud policy turned on (PMG v0.35.0-edge.1 and later), PMG on the endpoint sends its `reported/` [labels](/concepts/labels) and fetches its resolved policy. See [Policy Resolution](/concepts/policy-resolution).
