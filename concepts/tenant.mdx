A tenant is your organization's isolated space in SafeDep Cloud. Your users, API keys, policies, scan data, and endpoints all live inside it, separate from every other tenant.

## Your tenant ID is your tenant domain

The tenant identifier is a domain with three parts in the form `<team>.<organization>.safedep.io`, for example `your-team.your-org.safedep.io`. The **Tenant ID** button on the [API keys settings page](https://app.safedep.io/settings/api-keys) shows your tenant domain. There is no separate tenant ID to look up. You use the domain to:

- send the `X-Tenant-ID` header on API requests,
- configure Vet with `vet auth configure --tenant your-team.your-org.safedep.io`,
- set the `SAFEDEP_TENANT_ID` environment variable.

The safedep CLI selects the tenant when you run `safedep auth login`. If you can access more than one tenant, it asks you to select one. It stores the tenant in the active credential profile. To use a second tenant, sign in again with another profile, such as `safedep auth login --profile staging`, and pass `--profile` on each command.

## Why it matters

The tenant is the boundary for isolation and governance. Scan results, policies, and access are all scoped to it. You create and manage API keys inside your tenant from the SafeDep Cloud console.
