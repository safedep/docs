A policy turns your supply chain rules into data that SafeDep tools apply to each package. You write a rule once, and the tools apply it the same way on every machine and in every check. SafeDep has two kinds of policy. They differ in where they live, who changes them, and which tools read them.

## The cloud policy

The cloud policy is one policy for each [tenant](/concepts/tenant). It lives in SafeDep Cloud, and an Owner or an Admin of the tenant changes it in SafeDep Cloud or with the [safedep CLI](/get-started/cli-tools). A change reaches every endpoint and every pull request check of the tenant with no new MDM package.

The cloud policy holds two kinds of content:

- **Policy settings** are typed values, such as the dependency cooldown or the lowest vulnerability severity that fails a pull request check. Settings come in layers. The layers are the SafeDep default policy, the policy base of the tenant, and policy overrides for groups of endpoints and projects. See [Policy Resolution](/concepts/policy-resolution).
- **Package rules** are block entries and trust entries for packages. See [Package Rules](/concepts/package-rules).

Each publish makes a new [policy revision](/concepts/policy-revisions). Each decision that a tool makes with the cloud policy names the revision and the rule or setting that decided. So you can explain a block, roll back a bad change, and show an auditor which policy applied on a date.

PMG and the pull request check enforce the cloud policy. Vet does not read it yet. See [Cloud Policy Settings](/reference/cloud-policy-settings) for the tool that enforces each setting.

## Policy as code

Policy as code is a YAML file of [CEL](/concepts/cel) rules that you keep in a repository. Vet evaluates each package of a scan against the rules, including transitive dependencies, and you decide what a match does. During a local scan, Vet can exit with a non-zero code when a package matches a rule.

Vet reads two formats:

- **The v2 policy format** is the current format. Use it for a new policy. The Vet repository has the format, with a [v2 policy sample](https://github.com/safedep/vet/blob/main/samples/policy-v2.yml).
- **The filter suite format** is the older format. Vet marks it as deprecated. See [Policy as Code](/reference/policy-as-code) for its syntax and examples.

In CI/CD, [vet-action](/governance/integrations/github-code-scanning) takes a v2 policy file in its `policy-v2` input, or a filter suite in its `policy` input.

## Compare the two kinds

| | Cloud policy | Policy as code |
|---|---|---|
| Where it lives | SafeDep Cloud, one for each tenant | A YAML file in a repository |
| Who changes it | An Owner or an Admin of the tenant, in SafeDep Cloud or with the safedep CLI | Each person who can change the file |
| What it holds | Policy settings and package rules | CEL rules over package data |
| History | Policy revisions and audit events | The history of the repository |
| What enforces it | PMG and the pull request check | Vet and vet-action |
| Plan | SafeDep Cloud Team or Enterprise | Free and open source |
