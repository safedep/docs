[PMG](https://github.com/safedep/pmg) (Package Manager Guard) blocks malicious packages before they install. It wraps the package managers that you and your AI coding agents already use, so `npm install` and `pip install` do not change. Each install goes through the protection layers below.

PMG is free and open source under Apache 2.0. It uses SafeDep's free community API, with no account or API key.

## How PMG protects an install

Threat intelligence blocks known malware. For malware that is not known yet, the dependency cooldown and the sandbox limit what a new compromise can do.

| Layer | What it stops | Default |
|---|---|---|
| Threat intelligence | A known [malicious package](/concepts/malicious-package). PMG checks the full transitive dependency tree, not only the package you named. | On |
| [Dependency cooldown](/package-security/pmg/dependency-cooldown) | A version published in the last 2 days, when a new compromise is most likely to get through. | On |
| [Sandbox](/package-security/pmg/sandbox) | An install script that reads credential files, secret environment variables or the SSH agent, or writes to Git hooks. | Off |
| [Network policy](/package-security/pmg/network-policy) | An install that connects to a host that is not on the list, such as an attacker's server. | Off. Audit mode when you turn it on. |
| [Kernel enforcement](/package-security/pmg/kernel-enforcement) | A process that tries to bypass the PMG proxy. | Off. On by default in the GitHub action on GitHub-hosted runners. |

With the [cloud policy](/package-security/pmg/cloud-policy) turned on, PMG also applies the block entries, trust entries and cooldown of your SafeDep Cloud tenant. The cloud policy needs the Team or Enterprise plan.

## Platform support

| Capability | macOS | Linux | Windows |
|---|---|---|---|
| Threat intelligence and dependency cooldown | Yes | Yes | Yes |
| Sandbox and network policy | Yes (Seatbelt) | Yes (Landlock or Bubblewrap) | No |
| Persistent proxy in the background | Yes | Yes | Foreground only |
| Kernel enforcement | No | Yes | No |

For CI runners and shared Linux hosts, see [PMG in GitHub Actions](/package-security/pmg/github-actions) and [Kernel Enforcement](/package-security/pmg/kernel-enforcement).

The sandbox can also run an AI coding agent such as Claude Code, Codex or Pi. See [Sandbox Your AI Coding Agent](/ai-security/sandbox-coding-agents).

## Supported package managers

| Ecosystem | Package managers | Runners | Status |
|---|---|---|---|
| npm | `npm`, `pnpm`, `yarn`, `bun`, `aube` | `npx`, `pnpx`, `aubx`, `aubr` | Supported |
| PyPI | `pip`, `poetry`, `uv` | `pipx`, `uvx` | Supported |
| Go | `go` | | Experimental |
| Cargo | `cargo` | | Experimental |

On Windows, PMG does not support `aube`, `aubx` and `aubr` yet.

To check packages from an internal registry or mirror, see [Private Registries](/package-security/pmg/private-registries). For dependency resolution internals and CLI flags, see the [PMG repository](https://github.com/safedep/pmg).

<Note>
  Connect PMG to [SafeDep Cloud](/governance/cloud/overview) and the installs it checks sync to [Endpoint Hub](/governance/cloud/endpoint-hub/overview) as Package Guard events, a timeline of package activity across your team's endpoints. Local blocking works the same with or without an account. To send malicious and cooldown blocks to Slack or a webhook, see [Alerts](/governance/cloud/alerts).
</Note>
