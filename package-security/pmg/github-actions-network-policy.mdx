A compromised package can send your CI secrets to a host that the attacker controls. A network policy lists the hosts that a job can reach. The PMG proxy refuses every other destination, and the job fails.

<Note>

Use the policy with [kernel enforcement](/package-security/pmg/github-actions#enforce-in-the-kernel). Without it, a process can ignore the proxy variables and connect directly.
</Note>

## Build the policy from a run

The proxy records every destination that a job reaches. At the end of the job, the post step of the action proposes a profile from these destinations and shows it in the job summary.

<Steps>
  <Step title="Run the job with the action">
    ```yaml
    - uses: safedep/pmg@v0.34.0
      with:
        enforce: true

    - run: npm ci
    ```

    The job summary proposes a profile for `.pmg/network.yml`. To propose it for another path, set `network-profile` to a path that does not exist yet. The proposal comes from the event log, so do not set `skip-event-logging: true` or `baseline: false`.
  </Step>
  <Step title="Review the proposal">
    The proposal has one allow rule for each host that the job reached. It inherits the built-in `github-actions` profile, which allows the hosts of the runner and refuses every host that no rule allows. One run does not reach every host that the job needs. Remove each host that the job does not need.
  </Step>
  <Step title="Commit the profile">
    Save the proposal as `.pmg/network.yml`, commit it, and set `network-profile` on the action:

    ```yaml
    - uses: safedep/pmg@v0.34.0
      with:
        enforce: true
        network-profile: .pmg/network.yml
    ```

    `network-mode` is `audit` by default. Each later run lists the destinations that the profile does not allow, in the summary and as a warning on the run. The summary shows the rules to add.
  </Step>
  <Step title="Protect the profile">
    The profile controls what the job can reach, so give it the same review as the workflow file. Add a `CODEOWNERS` line:

    ```text
    .pmg/network.yml @your-org/security
    ```
  </Step>
</Steps>

A committed profile looks like this:

```yaml .pmg/network.yml
name: network
inherits: github-actions
network:
  deny_ip_literals: true
  allow_outbound:
    - registry.npmjs.org:443
  deny_outbound:
    - "*:*"
```

`deny_ip_literals` refuses a connection to an IP address that is not explicitly allowed. Without it, an allow list of names does not stop a package that sends data to an IP address.

## Enforce the policy

Set `network-mode: enforce`:

```yaml
- uses: safedep/pmg@v0.34.0
  with:
    enforce: true
    network-profile: .pmg/network.yml
    network-mode: enforce

- run: npm ci
```

The proxy refuses each destination that the profile does not allow. The post step fails the job, and the job summary names the destination, the rule, and the program.

The two inputs control different things:

| Input | What it controls |
| --- | --- |
| `enforce: true` | Which connections reach the proxy. The Linux kernel sends every process on the runner through the proxy, so a step cannot go around it. |
| `network-mode: enforce` | What the proxy does with a destination that the profile does not allow. `enforce` refuses the connection. `audit`, the default, lets it through and records it. |

Use both. Without `enforce: true`, a process that ignores the proxy variables connects directly, and the profile never sees the connection.

To add a host later, run the job with `network-mode: audit` and add the rule that the summary shows. Under `enforce`, the proxy refuses a new destination, so the proposal gets no rule for it.

## Hosts of the runner

Make your profile inherit `github-actions`. This built-in profile allows the hosts of the runner, its agents, GitHub releases, the GitHub container registry, and the cache and artifact storage. To see the hosts, run:

```bash
pmg sandbox profile show github-actions
```

Do not inherit another built-in profile, such as `npm-restrictive`. It does not allow the hosts of the runner, so the proxy refuses the connections of the runner to GitHub.

The runner, `actions/cache`, and `actions/upload-artifact` store data in Azure storage. `github-actions` allows only the storage accounts that the [GitHub Meta API](https://api.github.com/meta) lists, not every Azure storage account. When GitHub adds a storage account, a job under `network-mode: enforce` fails, and the job summary names a denied `productionresultssa<N>.blob.core.windows.net` host. Add that host to `network.allow_outbound` in your profile. You do not need a new PMG release.

An action that downloads from another host also needs a rule in your profile.
